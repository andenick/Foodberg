# 🚀 Foodberg.org Production Deployment Guide

## **Quick Overview**
Foodberg is a professional chef-focused food commodity pricing platform with:
- **Next.js 14 frontend** - Server-side rendering, optimized for SEO
- **Node.js Express backend** - Real-time USDA data integration
- **69+ commodities** - Comprehensive ingredient database
- **Professional dark theme** - Kitchen-optimized interface
- **Mobile responsive** - Works on tablets/phones during service

## **🎯 Recommended Deployment: Vercel + Railway**

### **Step 1: Frontend Deployment (Vercel)**
```bash
# 1. Install Vercel CLI
npm i -g vercel

# 2. Login to Vercel
vercel login

# 3. Deploy to production
npm run deploy:vercel

# 4. Configure custom domain
vercel domains add foodberg.org
```

### **Step 2: Backend Deployment (Railway)**
```bash
# 1. Push to GitHub repository
git add . && git commit -m "Production ready"
git push origin main

# 2. Connect to Railway
# - Visit railway.app
# - Connect GitHub repo
# - Deploy from /server directory
# - Set environment variables

# 3. Configure Railway environment:
# NODE_ENV=production
# PORT=3001
# CORS_ORIGIN=https://foodberg.org
```

### **Step 3: Environment Configuration**
```bash
# Vercel Environment Variables:
NEXT_PUBLIC_API_URL=https://your-railway-url.railway.app
NEXT_PUBLIC_SITE_URL=https://foodberg.org
USDA_API_KEY=your_usda_api_key

# Railway Environment Variables:
NODE_ENV=production
PORT=3001
CORS_ORIGIN=https://foodberg.org
```

## **🐳 Alternative: Docker Deployment**

### **Full Stack Docker**
```bash
# 1. Build and deploy with docker-compose
npm run deploy:docker

# 2. Configure SSL certificates
mkdir ssl
# Add your SSL certificates to /ssl folder

# 3. Start production stack
docker-compose -f docker-compose.production.yml up -d
```

### **Individual Docker Builds**
```bash
# Frontend
docker build -t foodberg-frontend .
docker run -p 3000:3000 foodberg-frontend

# Backend
cd server
docker build -t foodberg-backend .
docker run -p 3001:3001 foodberg-backend
```

## **🔄 Continuous Deployment**

### **GitHub Actions (Recommended)**
```yaml
# .github/workflows/deploy.yml
name: Deploy to Production
on:
  push:
    branches: [main]
jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - uses: actions/setup-node@v3
      - run: npm ci
      - run: npm run build:production
      - uses: amondnet/vercel-action@v20
```

### **Automatic Data Updates**
```bash
# Cron job for data collection (runs every 4 hours)
0 */4 * * * cd /path/to/foodberg && npm run data:collect
```

## **🚨 Emergency Procedures**

### **Rollback Process**
```bash
# Vercel rollback
vercel rollback

# Railway rollback
# Use Railway dashboard to redeploy previous version

# Docker rollback
docker-compose -f docker-compose.production.yml down
# Deploy previous image version
```

### **Data Backup**
```bash
# Backup historical data
tar -czf foodberg-data-$(date +%Y%m%d).tar.gz data/

# Backup to cloud storage (recommended)
aws s3 cp data/ s3://foodberg-backups/$(date +%Y%m%d)/ --recursive
```
